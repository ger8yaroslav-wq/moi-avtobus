# Архитектура

## Поток данных

1. `AddRouteActivity` и `StopSearchClient` помогают выбрать остановку и
   направление.
2. `ConfigurationStore` сохраняет список `RouteConfig` локально. Если
   конфигурации ещё нет (чистая установка), оно один раз создаёт три раздела к
   метро «Саларьево» с объединёнными 272 и 420. Сохранённый пустой список
   остаётся пустым, поэтому удалённые пользователем маршруты не появляются снова.
3. `EtaWorker` запускает `CityArrivalProvider` в фоне.
4. `CityArrivalProvider` группирует маршруты по координатам остановок, сочетает
   `stop/near`, `direction/forecasts` и резервное `direction/schedule`, затем сохраняет два
   ближайших времени и признак телеметрии через `AppPrefs`.
5. `BusWidgetProvider` объединяет прогнозы по пользовательским группам и
   `mergeId`, сначала выбирает до двух живых значений и только затем дополняет их
   расписанием, после чего формирует `RemoteViews`.
6. `RefreshScheduler` отвечает за периодические запросы, минутный обратный
   отсчёт и обновление после ожидаемого прибытия.

## Варианты виджетов

- `BusWidgetProvider` — адаптивный тёмный;
- `LightBusWidgetProvider` — адаптивный светлый.

Виджет определяет размер через `AppWidgetManager`. Большой размер показывает все разделы,
однострочный — выбранный раздел. Во всех размерах времена разделяются линией: `2 | 5 мин`, а в 1×1 показывается `2 | 5`.

## Хранение

Используются `SharedPreferences`. Сохраняются маршруты, ближайшие времена,
признак телеметрического прогноза и выбранный раздел каждого мини-виджета.
Секретов и API-ключей в проекте нет.
